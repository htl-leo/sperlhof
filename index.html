Was ist OpenSpec?

📄

Eine Sprache

OpenAPI (früher Swagger) ist ein offener Standard zur Beschreibung von HTTP-APIs – maschinenlesbar und menschenverständlich.

🤝

Ein Vertrag

Frontend und Backend einigen sich auf eine Spezifikation, bevor Code geschrieben wird. Kein ewiges Nachfragen mehr.

⚙️

Ein Generator

Aus einer YAML-Datei entstehen automatisch Clients, Server-Stubs, Tests und Dokumentation – in jeder Sprache.

Die Welt ohne Spezifikation

Chaos

  • Endlose Slack-Nachrichten
  • „Was gibt der Endpoint zurück?"
  • Frontend wartet auf Backend
  • Fehler erst in Production
  • Docs veraltet nach Woche 1
  • Kein Vertrag = keine Tests

Mit OpenSpec

  • Ein File = die Wahrheit
  • Mock-Server sofort verfügbar
  • Parallel entwickeln
  • Validierung automatisch
  • Docs immer aktuell
  • Contract-Tests out-of-the-box

So sieht eine Spec aus

# openapi.yaml – dein API-Vertrag
openapi: "3.1.0"
info:
  title: Pet Store API
  version: "1.0.0"

paths:
  /pets/{id}:
    get:
      summary: Ein Tier abrufen
      parameters:
        - name: id
          in: path
          required: true
          schema: { type: integer }
      responses:
        "200":
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Pet" }
        "404": { description: Nicht gefunden }

Der Spec-First-Workflow

  • 1

    Design

    Definiere Endpoints, Datenmodelle und Fehler in YAML/JSON – im Team, nicht solo.

  • 2

    Review

    PR-Review der Spec wie normaler Code. Alle sehen Änderungen, bevor sie implementiert werden.

  • 3

    Mock & Parallel

    Frontend nutzt Mock-Server (prism, Mirage.js). Backend implementiert gleichzeitig.

  • 4

    Validate & Ship

    CI prüft automatisch: Request/Response müssen zur Spec passen. Kein Vertrag, kein Merge.

Das Ökosystem

🖊️

Swagger Editor

Browser-Editor mit Live-Preview und Validierung. Ideal zum Starten.

📚

Swagger UI

Automatische, interaktive Doku direkt aus der Spec – kein Copy-Paste mehr.

🎭

Prism

Mock-Server in Sekunden. Frontend kann sofort loslegen, Backend noch nicht fertig? Egal.

🏗️

openapi-generator

Generiert Clients für TypeScript, Python, Go, Java, … – nie wieder HTTP-Boilerplate schreiben.

🧪

Schemathesis

Property-based Tests aus der Spec. Findet Bugs, die du nicht erwartet hast.

Geschichte der OpenAPI

2010
Swagger wird von Tony Tam bei Wordnik entwickelt – internes Tool.
2011
Swagger wird Open Source. Community wächst explosionsartig.
2015
SmartBear kauft Swagger. OpenAPI Initiative gegründet (Google, Microsoft, IBM, …).
2017
OpenAPI 3.0 – großer Relaunch mit sauberer Struktur und Komponenten.
2021
OpenAPI 3.1 – vollständige JSON Schema Kompatibilität. Heutiger Standard.

Warum du das lernen solltest

🚀

Sofort produktiv

Spec lesen = API verstehen. Du musst niemanden fragen – der Vertrag ist da.

💬

Besser kommunizieren

Eine Spec-Änderung sagt mehr als 20 Slack-Nachrichten. Du wirst zum klarsten Entwickler im Team.

🔧

Weniger Bugs

Validierung passiert automatisch. Typo in einem Feldnamen? CI schlägt an, bevor es jemand merkt.

Marktwertsteigerung

Fast jedes moderne Team arbeitet API-first. OpenAPI zu kennen ist kein Nice-to-have mehr.

„Eine gut geschriebene Spezifikation ist wie ein guter Test – sie zwingt dich, über das Problem nachzudenken, bevor du anfängst, es zu lösen." — Frei nach Martin Fowler

Als Junior Developer glaubst du vielleicht, du musst erst coden lernen. Aber Design vor Code ist die Superpower der Profis – und OpenSpec ist dein Einstieg dazu.
